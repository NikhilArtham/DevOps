## 📅 DAY 1 — Process Management

<details><summary>1. What is a process?</summary>A process is a running instance of a program managed by the operating system.</details>

<details><summary>2. What is a PID?</summary>PID stands for Process ID. It uniquely identifies a running process.</details>

<details><summary>3. What is a PPID?</summary>PPID is the Parent Process ID. It identifies the process that launched the current process.</details>

<details><summary>4. What is the difference between ps and top?</summary>`ps` gives a point-in-time process snapshot, while `top` continuously monitors processes and system resource usage.</details>

<details><summary>5. What is the difference between top and htop?</summary>Both provide real-time monitoring. `htop` provides a more interactive and visual interface.</details>

<details><summary>6. What does ps aux show?</summary>It lists processes from all users in user-oriented format and includes processes without a controlling terminal.</details>

<details><summary>7. What does ps -ef show?</summary>It provides a full-format process listing, useful for viewing PID, PPID, user and the complete command.</details>

<details><summary>8. How do you find a specific process?</summary>Use commands such as `pgrep nginx`, `ps aux | grep nginx`, or `ps -ef | grep nginx`.</details>

<details><summary>9. What are common Linux process states?</summary>R = running/runnable, S = sleeping, D = uninterruptible sleep, T = stopped, Z = zombie.</details>

<details><summary>10. What is a zombie process?</summary>A zombie has finished execution but remains in the process table because its parent has not collected its exit status.</details>

<details><summary>11. What is a Linux signal?</summary>A signal is a notification sent to a process requesting or indicating an action or event.</details>

<details><summary>12. What does kill PID do?</summary>`kill PID` normally sends SIGTERM (15), requesting graceful termination.</details>

<details><summary>13. What does kill -9 do?</summary>It sends SIGKILL (9), which forcefully terminates a process and cannot be caught or handled by it.</details>

<details><summary>14. SIGTERM vs SIGKILL?</summary>SIGTERM allows graceful cleanup; SIGKILL cannot be handled and forcefully terminates the process.</details>

<details><summary>15. What is SIGINT?</summary>SIGINT is signal 2, commonly generated by Ctrl+C to interrupt a foreground process.</details>

<details><summary>16. What are SIGSTOP and SIGCONT?</summary>SIGSTOP pauses a process and SIGCONT resumes a stopped process.</details>

<details><summary>17. What is SIGHUP used for?</summary>Historically it means hangup. Many daemons use it to request configuration reload, but behavior depends on the application.</details>

<details><summary>18. What is the difference between kill -15 and kill -9?</summary>`kill -15` sends graceful SIGTERM; `kill -9` sends forceful SIGKILL.</details>

<details><summary>19. How would you troubleshoot a high-CPU process?</summary>Use `top/htop` to identify the PID, inspect it with `ps`, correlate with logs/application behavior, determine whether the load is expected, then remediate appropriately.</details>

<details><summary>20. Why is process management important for DevOps?</summary>It is fundamental to troubleshooting high CPU, hung applications, failed services, crashes, zombie processes and production incidents.</details>

## 📅 DAY 2 — Filesystems, Mounts, Inodes & Disk Troubleshooting

<details><summary>1. What is a filesystem?</summary>A filesystem is the structure and rules Linux uses to store, organize and retrieve files and metadata. Examples include ext4 and XFS.</details>

<details><summary>2. What is a mount point?</summary>A mount point is a directory where a filesystem is attached to the Linux directory tree, such as `/dev/sdb1` mounted at `/data`.</details>

<details><summary>3. What does df -h show?</summary>It shows filesystem-level capacity and usage in human-readable units.</details>

<details><summary>4. What is the difference between df and du?</summary>`df` reports filesystem-level usage; `du` investigates directory/file-level usage.</details>

<details><summary>5. How do you check inode usage?</summary>Use `df -i` or `df -ih`.</details>

<details><summary>6. Can a filesystem have free disk space but fail to create files?</summary>Yes. It may have exhausted its inodes even though block storage still has free space.</details>

<details><summary>7. What is an inode?</summary>An inode stores filesystem metadata such as permissions, ownership, timestamps, size and references to data blocks.</details>

<details><summary>8. What does lsblk -f show?</summary>It shows block devices along with filesystem type, UUID, labels and mount points.</details>

<details><summary>9. What is the purpose of findmnt?</summary>It provides structured information about mounted filesystems and their mount relationships.</details>

<details><summary>10. How do you mount a filesystem?</summary>Use `mount <device> <mount-point>`, for example `mount /dev/sdb1 /data`.</details>

<details><summary>11. What is /etc/fstab?</summary>It contains persistent filesystem mount configuration used during boot or with `mount -a`.</details>

<details><summary>12. What happens if /etc/fstab is configured incorrectly?</summary>A bad entry can cause mount failures and potentially boot or service problems, so it should be validated carefully.</details>

<details><summary>13. How do you find the largest directories?</summary>Use targeted `du`, for example `du -xh --max-depth=1 /var | sort -hr`.</details>

<details><summary>14. How do you find large files?</summary>Use `find` with size/usage information and sort the results, while avoiding unnecessarily broad scans on production systems.</details>

<details><summary>15. What does find -xdev do?</summary>It prevents `find` from crossing into other mounted filesystems.</details>

<details><summary>16. Why might df show a full filesystem while du does not explain the usage?</summary>A deleted file may still be open by a running process. `lsof +L1` can help identify such files.</details>

<details><summary>17. What causes inode exhaustion?</summary>Common causes include millions of tiny files, caches, session files, temporary files, log fragments and application bugs.</details>

<details><summary>18. What is your production disk troubleshooting flow?</summary>Check `df -h` and `df -i`, inspect `lsblk -f`/`findmnt`, drill into directories with `du`, find large files, identify the owning application, clean safely and prevent recurrence.</details>

<details><summary>19. Why should you avoid blindly running du / on production?</summary>It can scan huge numbers of files and cross into other filesystems, making the investigation expensive and noisy.</details>

<details><summary>20. Why should you not immediately rm large files during a disk incident?</summary>You first need to establish ownership, application impact, retention requirements and whether the file is actively being used.</details>

## 📅 DAY 3 — Permissions, Ownership, ACLs & sudo

<details><summary>1. What are Linux file permissions?</summary>Permissions control read, write and execute access for the owner, group and others.</details>

<details><summary>2. What do u, g and o mean in chmod?</summary>`u` = user/owner, `g` = group, and `o` = others.</details>

<details><summary>3. What does chmod 755 mean?</summary>Owner has `rwx`; group and others have `r-x`.</details>

<details><summary>4. What is the difference between chmod +x and chmod 755?</summary>`+x` adds execute permission without changing other permissions; `755` explicitly sets owner/group/other permissions to a defined mode.</details>

<details><summary>5. What does chmod -R do?</summary>It applies the permission change recursively to a directory and its contents.</details>

<details><summary>6. What does chown do?</summary>`chown` changes file ownership, such as `chown user:group file`.</details>

<details><summary>7. What is the difference between chown user:file and chown user:group file?</summary>The first changes the owner; the second changes both owner and group.</details>

<details><summary>8. What is an ACL?</summary>An Access Control List provides more granular permissions for specific users or groups beyond the traditional owner/group/other model.</details>

<details><summary>9. What does setfacl -m mean?</summary>`-m` means modify/add an ACL entry.</details>

<details><summary>10. What does setfacl -x do?</summary>It removes a specified ACL entry.</details>

<details><summary>11. What does setfacl -b do?</summary>It removes all extended ACL entries from the target.</details>

<details><summary>12. What is a default ACL?</summary>A default ACL on a directory defines ACL permissions inherited by newly created files and directories under it.</details>

<details><summary>13. What is the ACL mask?</summary>The mask limits the effective permissions of named users, named groups and the group class in an ACL.</details>

<details><summary>14. How do you inspect ACLs?</summary>Use `getfacl <file-or-directory>`.</details>

<details><summary>15. What is sudo?</summary>`sudo` allows an authorized user to execute a command with another user's privileges, commonly root.</details>

<details><summary>16. What does sudo -l show?</summary>It lists the commands the current user is permitted to run through sudo.</details>

<details><summary>17. Why use visudo instead of directly editing sudoers?</summary>`visudo` validates sudoers syntax before saving, reducing the risk of breaking sudo access.</details>

<details><summary>18. How do you troubleshoot Permission denied?</summary>Check the effective user with `whoami`/`id`, inspect permissions with `ls -l`, traverse parent directories with `namei -l`, inspect ACLs with `getfacl`, and verify sudo rules when applicable.</details>

<details><summary>19. What is the difference between Linux permissions and AWS IAM permissions?</summary>Linux permissions control access to Linux resources; AWS IAM controls authorization to AWS APIs/resources. Both layers can affect an operation.</details>

<details><summary>20. What is the safest approach to fixing a production permission issue?</summary>Identify the exact failing user/process and resource, understand the intended access model, make the smallest required change, verify it, and avoid broad permissions such as unnecessary 777.</details>

## 📅 DAY 4 — systemd Services, Dependencies & Restart Behavior

<details><summary>1. What is systemd?</summary>systemd is the init and service-management system commonly used by modern Linux distributions.</details>

<details><summary>2. What is systemctl?</summary>`systemctl` is the command-line interface used to inspect and control systemd units.</details>

<details><summary>3. What is the difference between start and enable?</summary>`start` starts a unit now; `enable` configures it to start automatically according to its enablement configuration, typically at boot.</details>

<details><summary>4. What is the difference between restart and reload?</summary>`restart` stops and starts a service; `reload` asks the service to reload configuration without a full restart when supported.</details>

<details><summary>5. What does systemctl status show?</summary>It shows unit state, recent status information, process details and commonly a tail of related journal output.</details>

<details><summary>6. What is a systemd unit?</summary>A unit is a systemd-managed resource such as a service, socket, timer, mount or target.</details>

<details><summary>7. What are the main sections of a service unit?</summary>Common sections are `[Unit]`, `[Service]` and `[Install]`.</details>

<details><summary>8. What does After= do?</summary>`After=` controls startup/shutdown ordering relative to another unit; it does not itself start that unit.</details>

<details><summary>9. What is the difference between Wants= and Requires=?</summary>`Wants=` creates a weaker dependency; `Requires=` creates a stronger dependency where failure/inactivation of the required unit can affect the dependent unit.</details>

<details><summary>10. What does Before= do?</summary>It specifies ordering so the current unit is started before the referenced unit when both are part of the transaction.</details>

<details><summary>11. What does Restart= do?</summary>It tells systemd when to automatically restart a service after it exits or fails.</details>

<details><summary>12. What is RestartSec=?</summary>It defines the delay before systemd attempts a service restart.</details>

<details><summary>13. Why might a service start and immediately exit?</summary>Possible causes include application errors, bad configuration, missing files, permission issues, invalid arguments, missing dependencies or a process that is designed to exit.</details>

<details><summary>14. How do you troubleshoot a failed systemd service?</summary>Start with `systemctl status service`, then inspect `journalctl -u service`, configuration, permissions, dependencies and the application itself.</details>

<details><summary>15. What does daemon-reload do?</summary>It makes systemd reload unit-file configuration after unit files have been changed.</details>

<details><summary>16. When should you run daemon-reload?</summary>After modifying or creating systemd unit files before starting/restarting affected units.</details>

<details><summary>17. What is the difference between active and enabled?</summary>`active` describes current runtime state; `enabled` describes whether the unit is configured to be started automatically through enablement links.</details>

<details><summary>18. How would you troubleshoot a service failing because of permissions?</summary>Check the service's `User=`, inspect the target path with `namei -l`, inspect ACLs with `getfacl`, and test access as the service user where safe.</details>

<details><summary>19. How can restart loops become a production problem?</summary>A failing service can repeatedly restart, generate noisy logs, consume resources and hit systemd's start-rate limits while the real root cause remains unresolved.</details>

<details><summary>20. How does systemd knowledge help on AWS EC2?</summary>Many EC2-hosted applications run as systemd services, so systemd is central to startup, restart, dependency and production troubleshooting.</details>

## 📅 DAY 5 — journalctl & Log-Driven Troubleshooting

<details><summary>1. What is systemd-journald?</summary>It is the systemd logging service that collects and stores journal entries from the system, services and other sources.</details>

<details><summary>2. What is journalctl?</summary>`journalctl` is the command-line tool used to query and inspect the systemd journal.</details>

<details><summary>3. What does journalctl -u do?</summary>`-u` filters journal entries for a specific systemd unit/service.</details>

<details><summary>4. What does journalctl -f do?</summary>`-f` follows new log entries in real time, similar to `tail -f`.</details>

<details><summary>5. What does journalctl -n do?</summary>`-n` limits the output to a specified number of recent entries, such as `journalctl -n 50`.</details>

<details><summary>6. What does journalctl -b do?</summary>`-b` filters logs for a boot session; `-b -1` can be used to inspect the previous boot.</details>

<details><summary>7. What does journalctl -p do?</summary>`-p` filters by log priority, such as error or warning.</details>

<details><summary>8. How do you filter logs by time?</summary>Use `--since` and `--until`, for example `journalctl --since "1 hour ago"`.</details>

<details><summary>9. What does journalctl -k show?</summary>`-k` shows kernel messages recorded in the journal.</details>

<details><summary>10. What does journalctl --no-pager do?</summary>It prints output directly instead of opening it in a pager such as `less`.</details>

<details><summary>11. What does journalctl -g do?</summary>`-g` filters journal messages using a pattern/regular-expression style match.</details>

<details><summary>12. How do you inspect logs for a failed service?</summary>Use `systemctl status service` and `journalctl -u service`, then narrow by time and priority as needed.</details>

<details><summary>13. Why should you look for the first meaningful error?</summary>Later errors are often consequences. The earliest relevant failure can reveal the actual root cause.</details>

<details><summary>14. How do you troubleshoot repeated service restarts?</summary>Inspect `systemctl status`, `journalctl -u`, restart configuration, exit codes, dependencies and the underlying application error.</details>

<details><summary>15. How do you check journal disk usage?</summary>Use `journalctl --disk-usage`.</details>

<details><summary>16. How can journal retention be reduced?</summary>Use appropriate journald configuration or controlled cleanup such as `journalctl --vacuum-time`, following the organization's retention requirements.</details>

<details><summary>17. What is log-driven troubleshooting?</summary>It means using timestamped application/system logs to build a timeline, identify the first meaningful failure and correlate it with system state and dependencies.</details>

<details><summary>18. How would you troubleshoot an application that suddenly returns database connection errors?</summary>Check application logs around the incident time, database/service health, DNS/network connectivity, credentials/configuration, connection limits and recent changes.</details>

<details><summary>19. How does journalctl differ from CloudWatch Logs?</summary>`journalctl` primarily queries local systemd journal data; CloudWatch Logs is an AWS-managed logging service used for centralized storage and analysis when configured.</details>

<details><summary>20. What is a strong production log-troubleshooting mindset?</summary>Start with the incident timestamp, narrow the search, find the first meaningful error, correlate across components, verify the hypothesis and only then remediate.</details>

## 📅 DAY 6 — grep, sed, awk, sort & xargs

<details><summary>1. What is grep used for?</summary>`grep` searches text and filters lines matching a pattern.</details>

<details><summary>2. What does grep -i do?</summary>`-i` performs a case-insensitive search.</details>

<details><summary>3. What does grep -v do?</summary>`-v` inverts the match and returns lines that do not match the pattern.</details>

<details><summary>4. What does grep -n do?</summary>`-n` includes matching line numbers in the output.</details>

<details><summary>5. What is sed used for?</summary>`sed` is a stream editor commonly used for substitution, deletion, selection and text transformation.</details>

<details><summary>6. What does sed 's/old/new/g' mean?</summary>`s` means substitute, `old` is the pattern, `new` is the replacement and `g` applies the substitution to all matches on each line.</details>

<details><summary>7. What is awk used for?</summary>`awk` is useful for field-based text processing, filtering, calculations and report generation.</details>

<details><summary>8. What are $1 and $NF in awk?</summary>`$1` is the first field and `$NF` is the last field of the current record.</details>

<details><summary>9. What does sort -n do?</summary>`-n` sorts values numerically rather than lexicographically.</details>

<details><summary>10. What does sort -r do?</summary>`-r` reverses the sort order.</details>

<details><summary>11. What does sort -h do?</summary>`-h` understands human-readable size suffixes such as K, M and G.</details>

<details><summary>12. What is xargs used for?</summary>`xargs` converts input items into command-line arguments for another command.</details>

<details><summary>13. Why can xargs be dangerous in production?</summary>Untrusted or incorrectly parsed input can result in unintended commands or arguments. Input handling and quoting must be considered carefully.</details>

<details><summary>14. How do grep, awk and sort work together?</summary>They can form a pipeline where `grep` filters, `awk` extracts/counts, and `sort` orders the resulting data.</details>

<details><summary>15. How would you find the most common HTTP status code in logs?</summary>Extract the status field with `awk`, count with `sort | uniq -c`, then sort the counts numerically in descending order.</details>

<details><summary>16. How would you investigate HTTP 500 errors?</summary>Filter logs for 500 responses, group them by endpoint/error, inspect timestamps and correlate with application/dependency logs.</details>

<details><summary>17. Why is piping useful in DevOps troubleshooting?</summary>It lets you progressively filter, transform and summarize large outputs without manually processing every line.</details>

<details><summary>18. What is the difference between grep and sed?</summary>`grep` primarily selects/matches lines; `sed` primarily transforms or edits streams of text.</details>

<details><summary>19. What is the difference between awk and cut?</summary>`cut` performs simple field/character extraction; `awk` provides programmable field processing, conditions and calculations.</details>

<details><summary>20. What is a production-safe approach to shell pipelines?</summary>Start with read-only inspection, validate assumptions on a small sample, quote variables appropriately, avoid destructive commands until verified, and understand each pipeline stage.</details>

## 📅 DAY 7 — Bash Scripting: Variables, Loops, Functions & Exit Codes

<details><summary>1. What is Bash?</summary>Bash is a Unix shell and scripting language commonly used for Linux administration and DevOps automation.</details>

<details><summary>2. What is a shebang?</summary>The shebang is the first line of a script that specifies its interpreter, such as `#!/usr/bin/env bash`.</details>

<details><summary>3. How do you define a Bash variable?</summary>Use `name=value` with no spaces around `=`, then reference it as `$name` or `${name}`.</details>

<details><summary>4. Why is quoting important in Bash?</summary>Quoting prevents unwanted word splitting and glob expansion and helps preserve values containing spaces or special characters.</details>

<details><summary>5. What is command substitution?</summary>Command substitution captures command output using `$(command)`.</details>

<details><summary>6. What do $0, $1 and $# mean?</summary>`$0` is the script name, `$1` is the first argument, and `$#` is the number of positional arguments.</details>

<details><summary>7. What does $@ mean?</summary>`$@` represents all positional parameters and, when properly quoted as `"$@"`, preserves argument boundaries.</details>

<details><summary>8. What does $? mean?</summary>It contains the exit status of the most recently executed command.</details>

<details><summary>9. What does $$ mean?</summary>It expands to the PID of the current Bash shell/process.</details>

<details><summary>10. What is an exit code?</summary>An exit code is a numeric status returned by a command. Conventionally, 0 means success and non-zero means failure.</details>

<details><summary>11. What is the difference between return and exit?</summary>`return` exits a function or sourced script context with a status; `exit` terminates the current shell/script.</details>

<details><summary>12. How do if conditions work in Bash?</summary>They execute commands based on the success/failure status of a test or command, for example `if command; then ... fi`.</details>

<details><summary>13. What is the difference between for and while loops?</summary>`for` is commonly used to iterate over a known list/range; `while` continues while a condition/command succeeds.</details>

<details><summary>14. What do break and continue do?</summary>`break` exits the current loop; `continue` skips to the next iteration.</details>

<details><summary>15. Why use functions in Bash?</summary>Functions improve reuse, structure, readability and maintainability.</details>

<details><summary>16. What does set -euo pipefail do?</summary>`-e` helps stop on unhandled failures, `-u` treats unset variables as errors, and `pipefail` makes a pipeline fail if a command within it fails.</details>

<details><summary>17. What are the limitations of set -e?</summary>Its behavior has context-dependent exceptions, so important operations should still use explicit error checks rather than relying on `set -e` alone.</details>

<details><summary>18. How do you syntax-check a Bash script?</summary>Use `bash -n script.sh`.</details>

<details><summary>19. How do you debug a Bash script?</summary>Use tracing such as `bash -x script.sh` or add targeted logging and explicit status checks.</details>

<details><summary>20. Why are exit codes important in CI/CD?</summary>CI/CD systems commonly use exit status to determine whether a step succeeded or failed. A script that hides failures can cause false-successful deployments.</details>

## 📅 DAY 8 — Bash Error Handling, Traps & Safe Automation

<details><summary>1. Why is explicit error handling important in automation?</summary>Automation must fail accurately and predictably so downstream systems do not treat a failed operation as successful.</details>

<details><summary>2. What does set -e do?</summary>It makes Bash exit when an unhandled command failure occurs, subject to Bash's context-dependent exceptions.</details>

<details><summary>3. What does set -u do?</summary>It treats expansion of unset variables as an error.</details>

<details><summary>4. What does set -o pipefail do?</summary>It makes a pipeline return a failure status when an earlier command in the pipeline fails instead of only using the final command's status.</details>

<details><summary>5. What is trap in Bash?</summary>`trap` registers commands to run when the shell receives specified signals or shell events.</details>

<details><summary>6. What is trap ... EXIT used for?</summary>An `EXIT` trap runs when the shell exits, making it useful for cleanup such as removing temporary resources.</details>

<details><summary>7. What is trap ERR used for?</summary>It can run a handler when a command failure is detected under Bash's ERR trap rules, useful for logging/debugging.</details>

<details><summary>8. What is graceful shutdown?</summary>It means handling termination signals, stopping work safely, releasing resources and exiting cleanly instead of abruptly terminating.</details>

<details><summary>9. Why handle SIGTERM in automation?</summary>Schedulers, service managers and container platforms commonly use SIGTERM to request graceful termination.</details>

<details><summary>10. What is mktemp used for?</summary>`mktemp` creates temporary files or directories with safer unique names, reducing collision risks.</details>

<details><summary>11. Why should temporary files be cleaned with a trap?</summary>A trap provides cleanup even when the script exits unexpectedly, reducing leftover temporary data.</details>

<details><summary>12. What is flock?</summary>`flock` provides file-based locking so concurrent executions of a job can be prevented or coordinated.</details>

<details><summary>13. Why is duplicate-job prevention important?</summary>Concurrent automation can race, overwrite data, deploy twice or create conflicting changes, especially in scheduled jobs.</details>

<details><summary>14. Why validate script input?</summary>Validation prevents invalid, unexpected or dangerous values from reaching commands and reduces automation failures.</details>

<details><summary>15. Why use Bash arrays for command arguments?</summary>Arrays preserve argument boundaries and are safer than constructing one large unquoted command string.</details>

<details><summary>16. What is the risk of rm -rf with an unquoted variable?</summary>An empty or malformed variable can cause deletion of an unintended path. Destructive commands should validate paths and use safe quoting such as `rm -rf -- "$dir"`.</details>

<details><summary>17. How would you make a deployment script safe if artifact copy fails after stopping a service?</summary>Use explicit checks, traps/cleanup, preserve the previous artifact where possible, validate the new artifact before switching, and restore service availability on failure.</details>

<details><summary>18. How do you make AWS CLI automation safer?</summary>Validate inputs, use explicit profiles/regions where needed, check exit codes, avoid destructive defaults, log actions and use dry-run capabilities where available.</details>

<details><summary>19. How do you safely automate Kubernetes rollouts?</summary>Apply the intended change, check command status, use `kubectl rollout status` with an appropriate timeout, inspect rollout/pod events on failure and return a non-zero exit code.</details>

<details><summary>20. What is the key principle of production Bash automation?</summary>Automation should be predictable, idempotent where possible, observable, safely recoverable and explicit about failures rather than assuming every command succeeds.</details>
